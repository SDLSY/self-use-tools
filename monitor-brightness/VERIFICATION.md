# 验证记录

环境：2026-11-13，Windows，系统 .NET Framework 4.8；使用系统 C# 编译器构建。正式 EXE 免安装，无需管理员权限。

## 已通过

- 构建正式 Windows EXE，无外部依赖。
- 发现 AOC Q27N3G5R4，读取亮度范围 0–100，启动值 70；跳过 1 个无法控制的内置屏。
- 启动只读取亮度，不覆盖硬件值。
- 部署 EXE 重复启动时，第二个进程退出，原进程打开面板。
- 面板关闭后保留托盘进程，并可再次打开。
- 在真实 Explorer 托盘隐藏区点击图标打开面板，切换焦点后收起；右键菜单“退出”正常结束进程。
- 100 次连续滑块变化、松开提交与同时刷新，界面保持响应，无崩溃。
- 连续 6 次重新枚举、释放旧物理句柄并恢复可用滑块。
- 实际写入无效时显示错误和硬件读数，停用滑块；刷新后恢复。
- 模拟控制失败的错误界面与刷新恢复路径（不等同于真实拔插）。
- 测试后确认硬件亮度仍为 70。

## 硬件写入限制

AOC 的 `SetMonitorBrightness` 和 VCP `0x10` 写入调用均返回成功，但写入 68、71、72 后都仍读回 70。延迟重读和改用另一接口也没有确认改变。Windows 的 AdvancedColor / HDR 在此屏上未开启；显示器预设、DCR、OSD 限制或链路原因仍未确定。用户选择先完成工具并保留错误提示。

程序不会将这种情况当作成功：写入后分次等待重读，必要时尝试 VCP 路径；仍不匹配即显示“显示器未应用亮度”，详细错误可悬停查看。实际背光调整尚未在当前硬件配置上验证成功。

物理拔插后的恢复、多台可控制外接屏同时连接，尚无实测条件；代码支持重新枚举和每屏独立滑块。
